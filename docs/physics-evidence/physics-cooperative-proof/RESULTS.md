# Isolated cooperative evaluator capability and exact numerical proof

The pinned APIs support the proposed shared-memory/block-barrier mechanism on actual NVIDIA GB10. The isolated 32-lane point evaluator matches the current serial implementation exactly on the frozen final corpus: **2448 source +2448 fresh-precompiled comparisons**, 78 output words each (pressure4, residual8, Jacobian64, validity1 and original ordered norm1). Source/package JSONL artifacts are byte-identical. No cooperative solver owner, automatic selector or production source change was implemented. No performance claim follows.

## Capability and ownership

`capability.mojo` uses pinned `max.gpu.sync.barrier` and `std.memory.stack_allocation` with `AddressSpace.SHARED`. All32 lanes write disjoint words; lane0 performs an ascending scalar sum after the barrier. Nine scratch-reuse epochs and three kernel invocations produced exact sums and intact canaries. This proves actual cross-lane visibility/reuse for that finite witness; it does not depend on assumed warp lockstep.

`evaluator.mojo` is an isolated module under this build directory. The helper's original scalar per-point arithmetic comes from repository `coupled_friction_math.mojo:89-114`, with output indexing and staged return bookkeeping adapted by `make-evaluator.py`. No external source was copied. Leader lane0 runs the original ascending pressure-mask selection, ordered dP/dx dots and ordered residual norm. Lanes0..count-1 compute independent point disk roots/residual pairs/Jacobian rows, with the original per-output loops and expression grouping. The64 disk bisections remain dependent and ordered. Up to28 lanes are inactive for point math; all32 participate in every barrier and loop phase. Count0 is included.

Four unconditional block barriers bracket initialization/input publication, pressure/dP publication, point completion, and output consumption before scratch reuse. A worker may return from its local point helper but never from the block kernel. Only lane0 writes control and final output; each point lane owns disjoint residual/Jacobian words and its completion-stage flag. Input words remain immutable. Canaries surround Float64 scratch and the unused flag region; unused point stages and global output guard words are checked. Each persistent kernel runs the full102-case corpus over eight alternating forward/reverse epochs; three kernel invocations also compare all cooperative output words with the first invocation. Source and fresh-package runs each compare every numerical word against their serial device counterpart, then against each other.

The shared layout is506Float64=4048bytes plus32Int32=128bytes, **4176 explicit shared bytes**, within the4192-byte design budget. Compiler local arrays/stack storage are additional, not included in that number. Point workers can compute bounded unconsumed arithmetic after an earlier point would fail. They never speculate a future Newton step or line-search trial. The leader truncates the produced outputs to the exact original ascending prefix and preserves partially populated arrays, including a residual written before a derivative failure. This is disclosed extra point work on rejected evaluations, not extra logical solver trials.

## Generated behavior

Installed compiler help advertises `--emit asm` GPU sidecars. GB10 reports compute capability12.1. A separate one-thread diagnostic emission for `--target-accelerator sm_121` generated PTX targeting sm_121a. The cooperative sidecar declares4048+128shared bytes and four `bar.sync 0` sites; the serial sidecar has no shared declarations/barriers. Both contain Float64 instructions including38 static FMA,17 division and3 sqrt sites; neither contains Float32 arithmetic or atomic instructions. The same static arithmetic-site counts do not prove identical instruction scheduling; the actualGB10 bit comparisons supply the numerical evidence.

PTX also declares local storage3712bytes for the cooperative kernel and5112bytes for serial. These are compiler local-stack declarations, not measured dynamic spill traffic, occupancy, register pressure or a performance result. The sidecars are diagnostic compiler output, not disassembly of the cubins loaded by the runtime. No contraction settings, precision flags, clock/cache/boost settings or profiler were changed. See `generated-behavior.json` and retained PTX sidecars.

## Retained attempts and limits

All unsuccessful frontend attempts remain: a reserved `out` name in the capability witness; wrong existing snapshot helper argument and pinned Array literal syntax in the reference capture; file iteration/reserved `case` syntax and StringSpan/integer parsing in the harness. These failed before GPU execution and were corrected without changing numerical arithmetic or relaxing gates. Exact inputs use signed decimal representations of UInt64 bits for pinned `Int` parsing, then preserve the same words by cast; no float text conversion occurs in the test-input reader.

The first source corpus also passed2448comparisons but its zero-metric disk witnesses unexpectedly remained valid: the disk multiplier regularized them. That original corpus, declaration, generator, source output and receipts are retained as `*-v1-preserved` and `source-*`. The final corpus replaces those mislabeled inputs with explicit nonfinite disk-failure witnesses and independently confirms first/middle/last rejection stages. Final qualification counts do not add the provisional2448records. There was no numerical equality failure.

Pinned `mojo precompile` rejects `--num-threads`; its help states that it archives non-elaborated portable code and performs no architecture-specific code generation. The failed flag receipt is retained. The corrected package-archive stage used process-only CPU affinity0 to bound execution to one CPU, without changing OS settings. Every actual executable and diagnostic code-generation build used `--num-threads 1`. The fresh47-module archive contains the isolated evaluator and unchanged repository math dependencies with namespace adaptation only; original sources and prior package artifacts were preserved. `--print-effective-target` is a read-only query that exits; its receipt is separate from the subsequent actual assembly emission.

Capability is demonstrated and this bounded corpus is exact. Exhaustive race freedom, exactness across other architectures/releases, integrated Newton/rank/first-accepted line-search control, fallback/body updates, full70-trajectory requalification, energy/rollback transactions and performance remain outside this proof. Existing original63/70 coverage and known strict translated SAME-TIME failure, two baseline64 convergence rejects and four old ledge limits remain; the separate75/75translation and12/12ledge suites do not inflate it. No replacement owner was integrated and no speed claim is made from this tiny harness. Stop here before full solver integration as requested.
