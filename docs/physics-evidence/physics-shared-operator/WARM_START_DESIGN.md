# Proposed next experiment: consecutive-step tangent-root seeding

Design and qualification plan only. No cache, API, kernel or warm-start behavior is implemented. Keep it a separate opt-in owner, based on the sealed qualified early-inner policy; select any shared-table baseline only after its measured result is sealed. Do not bundle compression, new pivoting, gate changes or dispatch changes.

## What the current sources actually provide

`lifecycle.mojo.BodyHandle` contains slot, generation and owner namespace. `lifecycle_kernels.command_transaction` increments generation on removal; an UPDATE keeps generation and can replace pose and velocities after validating immutable mass/inertia. Thus generation alone cannot detect teleport or a velocity edit. Mass changes are currently rejected for an existing body; removal/recreation changes generation. Forces and successful integration are separately committed transactions. There is no warm-cache integration/update epoch in this API today.

`shape_kernels.write_pair` writes eleven words: each shape's slot/generation/revision and attached body's slot/generation, followed by namespace. Reshape increments revision even for identical geometry; detach/orphan reconciliation increments shape generation. Keep the entire key, in canonical A/B order; slot-only matching is unsafe. Body and shape commands and orphan reconciliation are earlier separate commits and are not undone by a response rejection.

`box_box_kernels` emits a SAT feature 0…14 and ambiguity/coalescing flags. Face/edge transitions and near ties can change the feature. `pack_box_response` reduces up to nine witnesses to at most four, restoring canonical selected-point order, then writes world-space A/B witnesses and their midpoint. It writes the pair key for every selected point but does not retain SAT feature, a stable per-point ID, or local anchors. Point ordinal is not a lifetime identity. `GpuContactHistory` is a separate one-point sphere/sphere or sphere/box history owner; it neither owns this box/box manifold nor stores response impulses. Its PERSISTENT ID cannot be substituted for a box/box warm-cache key.

`tangent_axes(n,c,s)` chooses a least-aligned world axis and rotates the resulting tangent frame by the caller's c/s. Its chosen axis can switch as n moves, and c/s may change. `cached_tangent_kernels.pack_coupled_tangent_metrics` rebuilds the current basis/metrics each resolve. `pack_box_response` resets accumulated normal/tangent impulses to zero, computes restitution targets from the incoming velocities, derives residual tolerances, and records incoming kinetic energy. `_projected` snapshots the position-projected, pre-response bodies; `commit_response` publishes bodies only on summary success. Current root attempts start from the current **within-resolve** tangent accumulation and subtract that accumulation and normal impulses from qn/qt. None of this is a cross-step warm cache.

## Cache and correspondence

Cache the final accepted per-contact normal impulse λ_n and world-space tangent impulse J_t=t*x0+u*x1, in kg·m/s under m/s/kg engine units. λ_n is validation/projection metadata; only transported tangent components seed the next nonlinear root. Do not cache a force, disk multiplier, Jacobian, effective mass, Newton direction, position-correction impulse, or last sweep's residual. Rebuild all current operators and targets as today.

Use fixed bounded GPU-owned current/pending caches, at most 16 patches/64 points. A patch record contains the full eleven-word key, SAT feature/flags, point count, a successful response epoch, the immediately associated integration epoch, body update revisions, exact material/configuration stamps, dt, normal, and both bodies' local witness anchors for each selected point. Convert anchors using the body poses **after position projection**, the same poses that generated the packed witnesses: local_a=R_a⁻¹(wa−position_a), local_b=R_b⁻¹(wb−position_b). Shape local center/orientation are accounted for through the world witnesses and shape revision; body-local anchors still require both records. Retain the prior basis for diagnostics and J_t for transport. Check finite values, nonnegative λ_n, normal magnitude, impulse cap and cone before publishing the cache.

Add successful body UPDATE revisions, successful integration epochs and the last integration dt at the owning GPU registry transaction boundary in the proposed implementation. Direct `response.detection.world.bodies.submit` calls must be visible to this tracking; an opt-in wrapper that can be bypassed is insufficient. Counters never wrap; exhaustion disables warm reuse and uses cold operation. Store stamps only after the associated transaction commits. Existing counters/handles are not changed. First version invalidates on every successful body UPDATE, even if the new data happen to match; this covers teleport, pose and velocity edits without guessing a teleport distance. A rejected command must not advance a revision. Removal, recreation, foreign namespace, closed/replaced owner, reshape, detach and orphan changes cannot match.

Reuse only on the immediately next successful integration/response sequence, with no skipped integration, repeated resolve without integration, intervening successful UPDATE, or material/configuration change. Both the integration dt and resolve dt must match the cached step dt exactly; restitution, coefficient, iteration policy and budget must also match exactly; do not scale impulses by dt ratio in the first experiment. Forces may change through their existing valid command path between steps: they affect current velocities and the rebuilt problem, while the cache remains only a guess. Include abrupt-force trajectories in qualification. Separation/empty successful response removes unmatched cache entries. Recontact starts cold.

Freeze conservative correspondence thresholds before implementation: same pair key, same unambiguous/noncoalesced SAT feature, same reduced count, and an unambiguous bijection of *both* body-local anchors within ε_anchor=0.05 times the smallest half-extent of either shape (length units). Require old/new normal dot≥0.9999. Bound actual anchor drift rather than demanding bit-equal anchors, so small sliding steps can have a cache hit. Reject a match if any point has multiple candidates; no nearest-point tie break and no ordinal-only fallback. A point-count, feature, coalescing/ambiguity, normal or unmatched-point transition makes the whole patch cold. Other valid patches may still reuse. These thresholds decide whether to try a seed; they do not relax geometry or final solver gates. These are proposed first-experiment retention choices, not an existing identity guarantee. Larger sliding steps and changing manifolds may yield few hits, which must be reported. Freeze them before running qualification and do not tune them after observing timing.

For a matched point, project J_t onto the new tangent plane and compute seed components by dotting with the freshly computed t/u. This handles c/s rotations and least-axis basis switches without interpreting stale coordinate components in a new basis. Validate current basis as today. Initially project the seed into the disk μ·λ_n from the previous accepted normal impulse; treat this only as a bound for the initial guess. The current evaluator computes its own pressure and current cone. Do not copy old λ_n into the current normal accumulator.

## Initialization without double-applying impulses

Use **root seeding only**, with no initial impulse application to bodies. Keep `pack_box_response`'s current normal and tangent accumulators at zero and its targets, energy baseline, geometry, tolerances and `_projected` snapshot unchanged. At the first visit to a matched patch, construct qn/qt by subtracting only impulses actually accumulated in this resolve, then initialize a separate Newton variable `x_seed` from the transported cache. The current code uses x for both roles, so the proposed implementation must explicitly separate `old_tangent` from the root iterate. Subtracting the warm seed from qn/qt while bodies never received it would solve the wrong problem.

Evaluate pressure from the current NN/NT/targets at that root seed. It remains the normal controller's answer, including its original mask/minimum-norm policy. On finish, apply `(new_pressure−old_normal)` and `(new_tangent−old_tangent)` exactly once, as the current finish routine does. Subsequent visits within the same resolve start from the actual accumulated impulses, with no repeated cross-step seeding. Prior-frame impulses already influenced incoming body velocities; cached values are a guess for this frame's new impulses, not an instruction to replay last frame's body delta. The zero-friction branch remains cold and unchanged.

Preserve the first-eight-sweep early-inner stop, all outer/Newton/trial/disk caps, complete pivots, fallback arithmetic and final residual, physical-state, energy, cone and profile gates. Seed validity does not authorize early acceptance outside these rules. Work can change; canonical physical state must still pass `1e−10*(1+abs(reference))` in qualification, and all existing exact invariants remain exact.

## Cold fallback and transaction boundary

Before changing private response state, validate correspondence and seed fields. A miss, invalid seed or unavailable cache capacity starts the patch cold. A failed first seeded attempt retries that patch cold from exactly its entry bodies and accumulators, with existing attempt/finish/fallback semantics; neither attempt may partly publish bodies or impulses. Keep retry bounds finite and record why it was used.

If the entire seeded response fails an existing final gate, restore the private candidate from the retained position-projected snapshot, rerun packing and metric initialization to reset impulses/history/work/control state, and perform one bounded wholly cold response under the same policy. Recompute targets/energy from the restored pre-response velocities. Warm-added changes must never reach `_current` before success. If cold also fails, return the cold path's existing rejection code, retaining the warm reason in diagnostics, with exact response-entry body rollback and unchanged committed cache. Record both attempts without hiding rejection cost. External CPU physical-state comparison remains a qualification gate, not a new runtime CPU fallback.

Stage final cache entries only after the full solver validation succeeds. Body commit and cache publication must share the same success predicate, on the same single-caller synchronized stream, with no new fallible allocation or validation after body publication. The API must not expose a partially published pair. On rejection leave current cache bytes, count, epochs and identities untouched; private pending bytes are not published state. A previously committed integration or orphan reconciliation stays committed, as today. On retry, epoch/revision mismatch conservatively makes the cache cold. Successful empty response commits an empty cache. Close synchronizes and prevents later access. Cache storage/counters/guards and 32 GiB reserve are part of qualification.

## Qualification and measurement plan before any implementation

1. Freeze the distinct opt-in owner, correspondence/retry rules, source baseline, cache layout/budget and unchanged gates. Require GPU and independent CPU correspondence tests for identical anchors, duplicate/ambiguous candidates, reordered selected points, face/edge/coalesced transitions, basis switches and 0/45/90-degree c/s changes. Check generations/revisions/namespace reuse, successful and rejected UPDATE, reshape, force, dt/material changes, teleport, skipped steps, repeated resolve, owner close and epoch exhaustion. Check exact cache/body rollback through initial, midpatch, convergence, capacity, energy and cone rejection; poison inactive slots and adjacent guards.

2. Run source and fresh precompiled-package versions over the complete existing trajectory, rank, derivative, lifecycle, rejection, controller and affected regression suites. Keep original 63/70 accounting and known failures visible. Warm misses must match cold numeric/work output exactly; valid warm hits may change work but must pass the original physical-state tolerance, all residual/energy/cone gates and exact static/immutable/inactive/identity/rollback invariants. Do not weaken gates to accept a different root. A new failure stops this experiment with its evidence.

3. Add genuine consecutive trajectories for quiet support, coupled sliding, gradual motion, centered rebound, zero friction, empty/separated bodies, falling/recontact, force changes, tangent-basis transitions, count/feature changes and removal/reuse. Each owner starts from the same initial state once, then integrates **its own last accepted state** and uses its own last accepted cache. Compare every frame with the independent CPU reference and a separate cold owner from its own trajectory; also diagnose a cold solve at the same incoming warm state if needed. Never copy the cold output into the warm trajectory, reset isolated steps and call that consecutive evidence, or hide accumulated divergence.

4. Only after correctness, freeze finite balanced whole-trajectory cold/warm ordering, warm-up exclusions and sample counts. Report per-frame/whole-trajectory API and GPU time, hit/miss/invalidation reasons, Newton/linear/residual/trial/sweep counts, cold retry cost, cache bytes and measured memory. Include all setup/first-contact/miss costs, rebound/zero-friction/empty controls and regressions. No favorable reruns, denied-counter retry or dynamic spill/stall claim. Use one execution slot, pinned toolchain, one-thread builds, finite per-stage guards and the existing 32 GiB reserve. Stop at the qualified bounded result.

This proposal intentionally seeds tangent roots rather than pre-applying normal/tangent impulses. Normal warm accumulation, looser anchor retention, dt scaling, feature interpolation and cache persistence across missed steps would each need a later distinct experiment.
