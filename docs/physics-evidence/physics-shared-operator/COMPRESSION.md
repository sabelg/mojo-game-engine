# Operator storage assessment (source inspection; no compression implementation)

The moved object is 256 Float64 words (2,048 bytes): sixteen mask blocks, each with fixed 4×4 row-major storage. It is **not** one 16×16 matrix. For a reduced patch of n≤4 contacts, `box_response_math.mask_operators` constructs each column by calling `pseudoinverse` with q[col]=−1. Block m is the embedded, rank-aware pseudoinverse of the normal effective-mass Gram submatrix selected by m. `valid[m]` records the existing negative-eigenvalue rejection. Mask zero is the zero operator. Mask order, minimum-norm selection and ties matter.

`box_response_kernels.metric` constructs NN (4×4 storage). It maps normal impulses to relative normal velocity, with contributions from inverse masses and the two bodies' inverse inertias and moment arms. NN is algebraically symmetric positive semidefinite in the supported physical domain; it can be rank deficient. Its pseudoinverse has mass units (kg if engine length/time/mass units are m/s/kg). Multiplication −O_m q produces normal impulse, kg·m/s. The table also computes dP/dx=−O_m NT for the pressure derivative. It is read by the normal-mask controller and fallback; workers computing point residuals do not read it.

The full contact velocity metric has NN, NT and TT blocks: n normal components and 2n tangent components, conceptual dimensions 3n×3n, with NT coupling and its algebraic transpose. Actual storage is NN[16], NT[32], TT[64]. These are distinct from the sixteen normal mask operators. Cross-contact entries inside an active mask need not be zero. Mask blocks overlap mathematically but represent different selected subspaces; a submask pseudoinverse cannot generally be recovered by taking a subblock of the full-mask pseudoinverse.

Outside each mask's selected rows/columns, and beyond n, entries are structural zeros. The n-contact mask family has sum(popcount(m)^2) potentially nonzero words: 0, 1, 6, 24, 80 for n=0…4. The full four-contact representation therefore has at most 80 such words out of 256 (640 versus 2,048 payload bytes before indexing/metadata). Removing only the n-padding while retaining dense n×n blocks would store 0, 2, 16, 72, 256 words. Packing selected rows/columns per mask could reach the first counts, with an explicit offset/index scheme. These are storage counts, not measured speedups.

The retained source obtains columns through separate Float64 pseudoinverse evaluations. Algebraic symmetry does **not** establish stored-bit symmetry. `operator-structure.json` inspects the twelve original real inputs in the saved controller corpus: 48 of 192 valid mask blocks have unequal mirrored Float64 bits, with maximum numeric asymmetry 2.220446049250313e−16. All 2,112 inspected numeric zeros were positive-zero bits; no structural-zero violation was found. This is bounded corpus evidence, not a universal signed-zero proof. Triangular storage with mirrored reconstruction would change retained values. Symmetrizing them would be an arithmetic change, outside this experiment. Dropping zero products can also change signed-zero/NaN behavior or accumulation order, so even structural packing would need an explicit reconstruction and exact-equivalence qualification.

The complete-pivot `coupled_friction_math.linear8` factors **the current nonlinear tangent residual Jacobian**, not NN, TT or the mask table. The root variable x has 2n tangent impulses; F_i(x)=x_i−disk_min_i(velocity(x,P(x)), μP_i(x)). Its Jacobian occupies fixed 8×8 storage with a live 2n×2n block. The point derivative includes dP/dx, active friction-disk derivatives and radius coupling. It need not be symmetric or SPD. The retained solver uses full row/column pivot search, the existing 256·EPS rank cutoff, and null-space projection for its rank-deficient minimum-norm direction. Cholesky or symmetric packing is not justified by the normal Gram's properties.

For n<4, packing the nonlinear Jacobian to (2n)^2 words, NT to 2n² and TT to 4n² could omit padding, but it would change indexing and loop/storage behavior and needs separate gates. No such change is made. This candidate only moves the original table bits into the existing shared slots 113…368; total shared allocation remains 4,176 bytes. The table is loaded once per patch visit in an outer sweep, reused across that visit's Newton/trial/final/fallback evaluations, and overwritten at the next visit. It is not retained across sweeps or physical steps.
