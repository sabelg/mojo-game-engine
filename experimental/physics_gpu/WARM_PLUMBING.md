# Seeds-disabled cache plumbing

`warm_plumbing_response.GpuWarmPlumbingBoxResponse` is a separate opt-in owner derived from the qualified shared-operator response. The existing owners, kernels, APIs and defaults are unchanged. It tracks and matches a bounded GPU cache but never passes cached impulses or the correspondence map to the solver. Seeds remain disabled on hits and misses, and solver numerics/work must remain exact.

It owns 13 additional fixed buffers, totaling 20,024 explicit bytes: 2,160 registry-tracking bytes and 17,864 cache/mapping/diagnostic bytes. Cache storage is fixed at 16 patches/64 points; `cache_patches` and `cache_points` can reduce admitted capacity without reducing allocation. Overflow makes the affected patch cold. No new solver shared memory is allocated; its 4,176-byte allocation is unchanged.

The isolated `warm_lifecycle`, `warm_collision` and `warm_box_box` owners preserve the original operations and public handle/command types. Direct nested body submissions are tracked on the same GPU stream after successful command commit. Successful UPDATEs advance per-body revisions; failed batches do not. Successful integration advances its epoch and stamps dt; failed steps do not. Exhaustion disables reuse without wrapping or changing the cold physics result. Body/shape/orphan transactions retain their existing separate commit boundaries.

The cache uses the complete eleven-word key, normalized by body slot order within the namespace: its normal points lower-to-higher body identity, its anchors follow that order, and its world tangent impulse is the impulse received by the higher body. Shape/solver order can differ: normal/impulse sign and anchors are swapped consistently, face features exchange A/B and edge features transpose axes. Current solver headers, geometry, spans and impulse order never change; only a current-point-to-old-cache-point map is produced.

Matching requires the immediate committed predecessor, exactly one integration, unchanged body UPDATE revisions and object identities, exact integration/resolve dt and material/policy compatibility, same unambiguous/noncoalesced feature and count, unit normals with dot at least 0.9999, and a unique bijection of both local anchors within 0.05 times the smallest half-extent. Invalid cached impulse/normal data also makes a patch cold. No nearest-point tie resolution is used. Basis rotation is compatible because the cached tangent impulse is a world vector.

Response attempt, committed response, and integration stamps are distinct. Rejection preserves committed cache bytes but breaks eligibility; a retry is cold. Successful repeated resolve without integration publishes an empty cache. Empty/separated success removes prior entries. Pending counts are cleared at every attempt and records are rebuilt from current packing; stale pending bytes never authorize publication. Cache publication shares the final summary success predicate and synchronized stream with body commit. No host consumer observes partial publication.

`cache_report()` returns eighteen Int64 counters, in order: lookups, hits, epoch misses, key/revision misses, material/dt/policy misses, feature/count/flags misses, normal misses, anchor misses, capacity misses, pending patches, pending points, publications, rejected summaries, seed uses (always zero), invalid cache data, ambiguous correspondence, and two reserved zeros. These diagnostics are separate from the unchanged ten solver work counters. Reading them is an explicit diagnostic operation, outside measured response wall time.
